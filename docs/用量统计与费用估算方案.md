# AI 精读与追问的用量统计与费用估算方案

> 状态：已全部实施（2026-11-26）——采集、计算、服务端帧、前端展示全通；验收 `npm run test:usage-pricing`（20/20）、`test:ask-context`（16/16）、`check`（56 文件）、`smoke` 全过，并用 mock 模型做了端到端实测
> 日期：2026-11-26
> 目标：让精读、追问（以及结构化）的 token 用量与估算费用可见

---

## 1. 背景与事实核实

调研 OpenAI 兼容协议与各家文档，确认三个关键事实：

1. **流式默认不返回 usage**。必须请求体带 `stream_options: { include_usage: true }`，usage 才会出现在最后一个 chunk——该 chunk 的 `choices` 是**空数组**，只有 `usage` 字段。当前 `streamChat()` 只解析 `choices[0].delta`，这个块会被直接跳过。
2. **各家行为不一**：OpenAI 需显式开 `stream_options`；DeepSeek / Kimi 即使不开也会在末帧注入 usage；自建网关 / Ollama 可能完全不返回。方案必须容忍"拿不到 usage"。
3. **费用不是简单的 输入×单价 + 输出×单价**：
   - DeepSeek 现在是**峰谷定价**（高峰 9:00-12:00 / 14:00-18:00 北京时间，其余空闲价为一半）；
   - 输入分**缓存命中 / 未命中**两档（V4-Flash 高峰 0.1 元 / 3 元每百万，输出 9 元）；
   - 因此要拿到 `prompt_tokens_details.cached_tokens`（DeepSeek 也返回 `prompt_cache_hit_tokens`）才能准确分档。

结论：**token 统计以服务商返回的 usage 为准，不自己数 token**；费用是按内置价格表的**估算**，界面必须标注"估算"。

---

## 2. 目标与非目标

### 目标

- 精读完成后显示本次 `输入 / 输出 / 缓存命中` tokens 与估算费用；
- 追问每条回答下方显示本次用量与费用；
- 结构化抽取（精读后的第二次调用）的用量并入精读合计；
- 拿不到 usage 时明确显示"—"或估算值，不静默为 0；
- 费用表覆盖内置预设，未知模型只显示 token、费用显示"未配置单价"。

### 非目标

- 不做精确账单 / 对账（那是服务商侧的事）；
- 不改 demo 模式行为；
- 不引入任何 SDK 或依赖；
- 本轮不接翻译引擎的费用（翻译是另一套服务与计价）。

## 3. 数据采集链路

### 3.1 请求侧：`buildBody` 加 `stream_options`

`server/shared/llm.mjs` 的 `buildBody()` 在 `stream: true` 时加：

```js
if (stream) body.stream_options = { include_usage: true };
```

兼容性风险：极少数自建端点遇到未知 `stream_options` 会报 400。处理方式：

- 对 `provider === 'custom' | 'ollama'` **不发送** `stream_options`（这些端点大多不支持，且本来也常无 usage）；
- 对内置预设（deepseek / kimi / openai / zhipu）发送；
- 若真实调用返回 400 且错误信息提到 `stream_options`，服务端记日志并提示用户，不自动重试（避免重复计费风险）。

### 3.2 解析侧：`streamChat` 接住 usage 块

当前循环里 `const choice = json?.choices?.[0]` 会跳过空 choices。改为：

```js
// 在 while 解析里，choice 处理之前
if (json?.usage && typeof json.usage === 'object') {
  lastUsage = normalizeUsage(json.usage);   // 见 3.3
  continue;                                  // 这个块没有内容
}
if (!json?.choices?.length) continue;         // 其它空 choices 心跳
```

生成器末尾把 usage 带出去：

```js
yield { channel: 'end', finishReason, usage: lastUsage };
```

注意：`[DONE]` 可能在 usage 块之后立即到达，当前代码 `break outer` 会跳出——usage 已被记录，没问题。

### 3.3 归一化 usage

统一成内部形状（放 `server/shared/usage.mjs`）：

```js
{
  prompt: Number,        // prompt_tokens
  completion: Number,    // completion_tokens
  cached: Number,        // 缓存命中输入；可能来自 prompt_tokens_details.cached_tokens
                         // 或 prompt_cache_hit_tokens，取第一个非负值
  total: Number,         // total_tokens，缺省 prompt+completion
}
```

容错：字段缺失一律记 0；`total` 缺省时本地相加；拿不到任何 usage 字段返回 `null`。

### 3.4 非流式调用

`completeChat()`（结构化抽取、导出摘要、连通性测试）的响应体自带 `usage`，直接归一化后返回：

```js
return { content, finishReason, usage: normalizeUsage(json.usage) };
```

不改变现有调用方的解构方式（多一个字段不影响）。

## 4. 费用估算

### 4.1 价格表（内置，可覆盖）

新建 `server/shared/pricing.mjs`，导出 `PRICES`：按 `provider + model` 精确匹配，支持通配前缀。数据以官方公开价为准，**以「元 / 百万 tokens」为单位**：

| provider | model | 缓存命中输入 | 未命中输入 | 输出 | 备注 |
| --- | --- | --- | --- | --- | --- |
| deepseek | deepseek-v4-flash / deepseek-flash | 0.1 | 3 | 9 | 高峰价，空闲减半 |
| deepseek | deepseek-v4-pro | 0.3 | 9 | 27 | 高峰价，空闲减半 |
| deepseek | deepseek-chat / reasoner | 0.02 | 1 | 2 | 旧线路兼容名 |
| openai | gpt-4o-mini / gpt-4o / gpt-4.1-mini / o4-mini | — | 待实施时按官网核对 | — | |
| kimi / zhipu | 预设型号 | — | 待实施时按官网核对 | — | |
| ollama / custom | 任意 | 0 | 0 | 0 | 本地模型视为免费 |

峰谷判定（仅 DeepSeek V4 系列）：按调用时刻的**北京时间** hour 判断是否在 9-12 / 14-18，命中则用高峰价，否则乘 0.5。

**价格会变**：文档里写明数据来源与核实日期（2026-11-26），界面 tooltip 注明"按内置参考价估算，以服务商账单为准"。

### 4.2 用户自定义单价

在 `config.json` 增加可选字段 `pricing`（不填则用内置表）：

```json
"pricing": {
  "deepseek-v4-flash": { "cached": 0.1, "input": 3, "output": 9, "peakOnly": true }
}
```

设置页加一个折叠的"价格参数"区，允许覆盖三个单价；留空用内置。

### 4.3 计算

```js
cost = cached/1e6 * price.cached
     + (prompt - cached)/1e6 * price.input
     + completion/1e6 * price.output
```

- 单价缺失 → `cost = null`，前端显示"未配置单价"；
- 缓存字段缺失但有 prompt → 全部按未命中算（保守上限）；
- 金额格式化：`¥0.0123`（4 位小数，小额也不显示为 0），≤0.0001 显示 `<¥0.0001`。

## 5. 前端展示

### 5.1 精读

- 状态栏 `#reading-status`：完成后由"已完成"变为
  `已完成 · 12.3k tokens · ¥0.05`；
- hover title 显示明细：`输入 10.2k（缓存 4.1k）· 输出 2.1k · 估算费用`；
- 结构化抽取的费用并入这个合计：`/api/structure` 响应里带 `usage` / `cost`，前端累加显示。

### 5.2 追问

- 每条 AI 回答下方加一行小字（`.ask-usage`）：
  `1.2k tokens · ¥0.01`，hover 看明细；
- `pushAsk()` 的 entry 增加可选 `usage` 字段，随 `askThread` 一起存进 `ask_json`，刷新后仍能显示；
- demo 模式不显示。

### 5.3 数据来源

服务端在 SSE `done` 帧带上 usage 与费用（新增字段，不影响老前端）：

```js
sse.event('done', { mode: 'live', usage: { ... }, cost: 0.05, currency: 'CNY', estimated: true });
```

`/api/structure` 在非 demo 分支的响应里带 `usage` / `cost`。

## 6. 容错与降级

| 情况 | 处理 |
| --- | --- |
| 服务商不返回 usage | `usage=null`，前端显示"用量未知"，费用不显示；不猜数 |
| 用户中途停止 | abort 后通常无 usage，显示"已中断 · 用量未知" |
| 未知模型 / 自定义端点 | 有 usage 显示 token，费用显示"未配置单价" |
| 价格表过时 | 界面注明估算；文档记录核实日期与来源链接 |
| 峰谷时段切换 | 用调用发起时刻判断，费用算一次即定 |
| usage 块晚于 [DONE] | 按协议 usage 必在 [DONE] 前；若真缺失则视为无 usage |

**实测算例**（DeepSeek V4-Flash，高峰）：输入 1000（缓存 400 + 未命中 600）+ 输出 200 → `0.00004 + 0.0018 + 0.0018 = ¥0.00364`；同用量空闲时段恰好半价。

测试中发现并修正两处：
1. `formatCost` 原用 4 位小数会把 ¥0.00364 截成 ¥0.0036，改为 6 位小数去尾零；
2. `custom` provider 原按免费处理，会把第三方收费端点误显示为 ¥0——改为只有 `ollama` 免费，custom 走"未配置单价"。

### Bug 修复：加载论文时精读用量被覆盖（同日）

现象：实测发现精读 tokens 用量丢失。根因在 `applyPaperRecord()`：先调用 `setPaper()`（内部有 `schedulePaperSave(300)` 异步保存），之后才恢复 `state.readingUsage = record.usage`。那个延迟保存会用尚未恢复的 null usage 覆盖数据库里正确的 `usage_json`。修复：把 `state.readingUsage = record.usage || null` 移到 `setPaper()` **之前**。验证：浏览器加载论文后数据库 usage / ask_usage 完好，累计徽标显示 `16k tokens · ¥0.0424`。

### 阶段 3：论文级累计（已实施）

- `server/paper/db.mjs`：`PAPER_COLUMNS` 加 `usage_json`（走已有的缺列补列迁移，不重建表）；
- `server/paper/library.mjs`：`toPaper()` 解析 `usage`，`savePaper()` 读写 `usage_json`；追问用量本就在 `ask_json` 的 entry.usage 里；
- `public/app.js`：`paperPayload()` 带 `usage`（精读+结构化的合计）；`applyPaperRecord()` 恢复 `state.readingUsage`；`totalUsage()` 合并精读+全部追问；`paintTotalUsage()` 渲染精读栏标题区的 `#total-usage` 徽标；清空/追问 done/恢复论文时同步刷新；
- `public/index.html` / `ui.css`：精读栏标题区加 `#total-usage` 徽标与样式。

端到端实测：精读 12.8k（¥0.0316）+ 追问 3.2k（¥0.0108）= 累计 `16k tokens · ¥0.0424`；论文 save → get 能读回 `usage` 与 `ask_thread[].usage`；从服务端恢复论文后徽标正确显示。截图 `docs/ui-preview/total-usage.png`、`total-usage-restored.png`。

### 阶段 2：服务端帧 + 前端展示（已实施）
