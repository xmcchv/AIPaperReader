# 三视图合并方案：翻译 / 精读 / 知识图谱（v2 · 已定稿）

> 目标：把 `D:\lcheng\papertrans` 并入 `AIPaperReader`，形成**一个进程、一个端口、一个 SQLite、三个可切换视图**；翻译页与精读页**共用左侧历史论文侧栏**；**PDF 分块以翻译页的 `extract.mjs` 为唯一真相**。

> v2 变更：六项决策已确认（见 §1），SQLite 合并进单一论文库文件，实施顺序按「先下线 Express、再合库、再统一分块」重排。v1 的「待拍板」章节已删除。

## 1. 已确认的决策

| # | 决策 | 落地含义 |
| --- | --- | --- |
| D1 | **`extract.mjs` 是唯一分块真相** | 分块结果写 `papers.blocks_json`；精读 PDF 视图不再自抽，改为消费同一份块 |
| D2 | **翻译引擎凭据迁入 `config.json` + 主密码加密** | 复用 `server/shared/secret.mjs`，与 LLM Key 共用一次解锁；`prefs.cfg` 明文方案废弃 |

| D4 | **Express 直接下线** | `lib/*.js` 改写为 `server/translate/*.mjs`，路由并入 `server/index.mjs` 风格；运行时依赖降为 0 |
| D5 | **翻译页打开 PDF 即入库** | 打开即写 `papers` + PDF 落盘 + 分块落库；按 `pdf_hash` 去重，同一份 PDF 不产生第二条记录 |
| D6 | **SQLite 合并** | 翻译侧全部表并入 `~/.paperlens/data/papers.db`；不再有 `.cache/papertrans.sqlite`（旧文件只读留存） |

### 3.3 单一论文库：`papers.db` 完整 schema

一个文件，四张表。所有 `ALTER` 都写成「缺列则补」，老库直接升级（照 `kg/store.mjs` 的写法）。

```sql
-- 论文主表：正文 + PDF + 分块 + 译文 + 精读 + 结构化 + 追问
CREATE TABLE IF NOT EXISTS papers (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL DEFAULT '',
  source TEXT NOT NULL DEFAULT '',          -- arXiv 链接 / 文件名 / 'papertrans'
  kind TEXT NOT NULL DEFAULT 'pdf',         -- pdf | text | arxiv
  text TEXT NOT NULL DEFAULT '',
  chars INTEGER NOT NULL DEFAULT 0,
  pdf_path TEXT NOT NULL DEFAULT '',
  pdf_hash TEXT NOT NULL DEFAULT '',        -- sha1(前 1MB + 字节数)：去重 + 判断换文件
  pages INTEGER NOT NULL DEFAULT 0,
  blocks_json TEXT NOT NULL DEFAULT '',     -- D1：唯一分块真相
  blocks_hash TEXT NOT NULL DEFAULT '',
  blocks_at TEXT NOT NULL DEFAULT '',
  seg_overrides_json TEXT NOT NULL DEFAULT '', -- 手动合并/拆分/顺序锁
  tr_json TEXT NOT NULL DEFAULT '',         -- [{text, zh}]，按原文文本为 key
  tr_engine TEXT NOT NULL DEFAULT '',
  tr_count INTEGER NOT NULL DEFAULT 0,
  reading_md TEXT NOT NULL DEFAULT '',
  reading_model TEXT NOT NULL DEFAULT '',
  structure_json TEXT NOT NULL DEFAULT '{}',
  ask_json TEXT NOT NULL DEFAULT '[]',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_papers_updated ON papers(updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_papers_hash ON papers(pdf_hash);

-- 全局翻译缓存（跨论文复用，key = sha1(engine|base_url|model + 原文)）
CREATE TABLE IF NOT EXISTS tr_cache (
  k TEXT PRIMARY KEY, zh TEXT NOT NULL, created_at INTEGER NOT NULL
);

-- AI 分段缓存（key = sha1(model + 页内行文本)）
CREATE TABLE IF NOT EXISTS seg_cache (
  k TEXT PRIMARY KEY, data TEXT NOT NULL, created_at INTEGER NOT NULL
);

-- 翻译页偏好 / 人工修正记录（原 kv 表）
CREATE TABLE IF NOT EXISTS prefs (
  k TEXT PRIMARY KEY, v TEXT NOT NULL, updated_at INTEGER NOT NULL
);
```

设计要点：

- **`papers` 一行管到底**：这篇论文的正文、PDF、分块、译文、精读、图解、追问都在一行，侧栏一条记录即完整上下文。
- **`tr_json` 与 `tr_cache` 分工**：`tr_json` 是这篇的译文（展示用、可编辑、可导出），`tr_cache` 是全局缓存（同句换论文可直接命中）。两者都在同一个库，不再跨文件。
- **块 id 用 `page:order`，不做长期稳定 id**；译文按文本 key，重排版/重分段不丢译文。
- **`pdf_hash` 是幂等键**：同 hash 复用 id（D5）。

### 3.4 分块统一（D1）

```
打开 PDF
  → 算 pdf_hash → GET 命中则复用 paperId，否则新建（D5）
  → extract.mjs 抽块（双栏 / 图表标注 / 顺序锁 / AI 分段全部生效）
  → POST /api/paper/blocks 落库
  ├─ 翻译视图：右栏卡片 = blocks by order；左栏热区 = block 矩形
  └─ 精读视图：pdfView.load(bytes, { blocks })
        · 框线 / 点击 / 闪烁都按 block
        · 「点击概念定位」命中的就是翻译卡片里那段
        · 框选问 AI：选区落在单块内直接取 block.text
        · blocks 缺失（扫描件 / 旧数据）→ 回退 pdfview 自抽，不阻塞
```

`pdfview.js` 只加一层：`state.paras = blocksToParas(blocks) || await selfExtract()`，`blocksToParas` 把 `{page,x,y,w,h,text}` 转成既有 `{id, text, rects:[…]}`，渲染与 `locate()` 全部复用，自抽逻辑留作降级。

### 3.5 共享侧栏（D3）

- DOM：`#paper-sidebar` 放在 `#view-*` 之外，`position: fixed` 占左列；`app-main` 用 `margin-left` 让位；`body[data-view=kg]` 时隐藏。
- 数据：`GET /api/paper/library`，一次拿全（`hasPdf / pages / blocksCount / trCount / hasReading / updatedAt`）。
- 列表项：标题 · 元信息（页数 · 段数 · 译文数 · 精读状态）· 当前项高亮 · 右键重命名/删除。
- 点击分派：翻译视图 → 载 PDF + blocks + 译文（无 PDF 则提示切精读）；精读视图 → 载 text / reading / structure / ask / PDF。
- 精读页「打开论文 → 论文库」标签页删除，侧栏是唯一入口；arXiv / 粘贴 / 上传成功后侧栏立即出现。

### 3.7 配置与凭据（D2）

```jsonc
// ~/.paperlens/config.json（config_version: 3）
{
  "provider": "deepseek", "base_url": "...", "model": "...",
  "api_key_enc": { /* scrypt + AES-256-GCM */ },
  "max_tokens": null, "temperature": 0.3, "extra_body": null,
  "vision_model": "", "vision_base_url": "", "vision_api_key_enc": null,
  "translate": {
    "provider": "free",
    "providers": {
      "deepseek": { "base_url": "https://api.deepseek.com/v1", "model": "deepseek-chat", "api_key_enc": {...} },
      "deepl":    { "base_url": "https://api-free.deepl.com", "model": "ZH", "api_key_enc": {...} },
      "baidu":    { "app_id": "...", "api_key_enc": {...} }
    }
  }
}
```

- **一次解锁解全部**：`POST /api/config/unlock` 同时解 `api_key_enc`、`vision_api_key_enc`、`translate.providers[*].api_key_enc`，明文只留在进程内存。
- `publicConfig()` 增 `translate: { provider, providers: { id: { base_url, model, app_id, has_key } }, ready }`，**任何 `*_api_key` 都不回前端**。
- 免费引擎（`free / microsoft / google / tencent / volc / yandex`）无 Key，只存 provider 名。
- `secret.mjs` 字节级复用，不改 KDF 参数；`config_version` 从 2 升 3，读旧文件时自动补 `translate` 段，写回时保留原 `api_key_enc`。
- 顺带修掉一个现存问题：`prefs.cfg` 里的 apiKey 是明文，迁移时加密落 `config.json`，迁完从 `prefs` 删除。

### 3.8 「打开即入库」的幂等流程（D5）

```
选文件 → 读字节 → sha1(前 1MB + size) = hash
  → POST /api/paper/open?name=…&hash=…
      ├─ 查 papers.pdf_hash = hash 命中 → 复用 id，返回已有 blocks/tr
      └─ 未命中 → 新建 papers(id=p_…, title=文件名, kind='pdf')
                 写 papers/<id>.pdf，回填 pdf_path / pdf_hash
  → 前端抽块 → POST /api/paper/blocks
  → text 为空时，用 blocks 按 order 拼正文 → POST /api/paper/save
```

三个后果，都是想要的：

1. 侧栏立刻有记录，不用「保存」动作。
2. 同一篇论文重复打开不产生重复项（hash 幂等），且保留原有译文。
3. 翻译页打开的论文天然可进精读（正文由 blocks 生成），两个视图真正闭环。

## 5. 数据迁移（单库合并）

`scripts/migrate-papertrans.mjs`，一次性、幂等、只复制不删除：

```
备份 cp ~/.paperlens/data/papers.db papers.db.bak
读 .cache/papertrans.sqlite（只读打开，不做 WAL 切换）
├── projects  → papers
│      id 原样保留（k_ 前缀，避免与 p_ 冲突）
│      title = name, kind='pdf', source='papertrans'
│      pages / chars / tr_count = data 里的值
│      seg_overrides_json = data.overrides
│      tr_json = data.translations（[{text,zh}]）
├── pdfs      → <DATA_DIR>/papers/<id>.pdf
│      pdf_path 回填；同时按 BLOB 算 pdf_hash（D5 去重的前提）
├── translations → tr_cache（k/zh 原样搬，created_at 保留）
├── segments     → seg_cache（同上）
└── kv        → prefs 表（corrections / font / split / remember …）
       cfg    → config.json 的 translate 段，apiKey 用主密码加密（迁移时要求输入一次）
       theme  → 丢弃（统一到 paperlens.theme）
       last   → /api/last
```

约束：

- **幂等**：`papers.id` 存在即跳过；重复执行不覆盖用户后来改过的译文。
- **只复制不删除**：`.cache/papertrans.sqlite` 原样留着，回滚不丢数据；迁移完成在日志里打印「原库保留在 …」。
- **失败可重入**：先写临时表校验行数，再合并；PDF 文件写入失败则不提交该行。
- 迁移后 `blocks_json` 为空，提示「首次打开翻译页会重算分块」——这是预期行为，不是丢数据（译文按文本 key，重算后仍命中）。

## 6. 实施步骤与验收

顺序调整说明：v1 打算先留 Express 过渡，现在 D4 明确下线，所以 **P0 就把翻译接口迁成主仓风格并用别名兜住旧路径**；D6 让 P1 变成「单库合并」，比 v1 多一步 schema 统一，但少了「两个库同步」的长期负担。

### P0 · 骨架 + Express 下线（1–1.5 天）

### 10.8 D1 落地：分块统一（翻译页 → 论文库 → 精读页）

链路：

```
翻译页 extract.mjs 抽块
  → applyBlocks() 之后 scheduleBlocksSave(600/1500ms)
  → POST /api/paper/blocks  { id, hash: docId, blocks:[{page,order,text,x,y,w,h,kind}] }
  → papers.blocks_json
  → 精读页 /api/paper/get 拿到 blocks → pdfView.load(bytes, { blocks })
      · blocksToParas()：PDF 空间（原点左下）→ 热区坐标（距页面顶部）
        y0 = pageHeight - block.y,  y1 = y0 + block.h
      · 概念定位 / 框选问 AI / 点块看卡片都跑在同一份 paras 上
```

实现要点：

1. **只结构变化才写库**。`blocksSignature = page:order:text.length` 的拼接，和上次相同就跳过；翻译一段不会触发一次分块写入。切换文档时清空签名，下一篇必写。
2. **精读不再自抽**。`pdfView.load(bytes, { blocks })` 有 blocks 就跳过 `getTextContent + buildPageParagraphs + mergeFlowingParagraphs`（省一遍解析），直接由块生成热区；没有 blocks 仍走原来的自抽，扫描件/新上传不受影响。
3. **正文口径统一**。只有 PDF 的论文，`state.text` 现在就是块的拼接结果；`state.paper.text` 为空时仍会自动补存。
4. **页码与顺序**：块的 `page` 存 0 基（pdfview 用 index），`order` 是跨页的全局阅读顺序（按 page + 页内 idx 排序后重编号），所以双栏、跨栏续段都按翻译页的阅读顺序落到热区上。

验证（本机实测 kiytsn0）：

| 检查 | 结果 |
| --- | --- |
| 翻译页打开后 `papers.blocks_json` | 121 块（= 卡片数），首块为 IEEE 版权声明 |
| 精读页热区数量 | 116 / 121（5 块在第 13 页，截图时该页还没渲染完） |
| 坐标一致性 | 首块 `w 514.07 → 304.914px`、`h 54.68 → 32.43px`、`x 58.92 → 34.95px`、`y 739.88 → top 30.92px`，比例都是 **0.593**，即同一个 scale，四条边全对得上 |
| `npm run check` / `npm run smoke` / 无头 Chrome | 48 文件 0 失败 / 通过 / 0 异常 0 控制台错误 |

已知边界：

- 精读页「＋PDF」直接上传的论文还没有 blocks（那台机器上没有 extract.mjs），第一次进翻译页抽完块并落库后，精读页刷新就会用共享分块。
- `blocks_hash` 目前存的是 `docId`（文件名 + 页数 + 字符数），只用于标识；还没有「PDF 换了但 id 没变」时的失效判断 —— 换 PDF 会得到新的 docId，所以实际不会串。
- 块的 kind 只有 `body / heading / caption`（翻译页把 annotation、formula 过滤掉了，它们本来也不需要翻译），所以精读页的热区也只覆盖这三类。

### 10.9 D2 落地：翻译引擎凭据加密

存储结构（`~/.paperlens/config.json`）：

```jsonc
{
  "provider": "deepseek", "base_url": "...", "model": "...", "api_key_enc": {…},   // 精读/图谱，未改
  "translate": {
    "provider": "deepseek",
    "providers": {
      "deepseek": { "base_url": "...", "model": "...", "app_id": "", "api_key_enc": {…} },
      "deepl":    { "base_url": "https://api-free.deepl.com", "model": "ZH", "api_key_enc": {…} }
    }
  }
}
```

- 加密复用 `secret.mjs`（scrypt + AES-256-GCM），**同一个主密码**同时解 LLM Key 和翻译 Key；明文只进进程内存（`unlockedTranslate: Map<providerId, key>`）。
- `POST /api/config/unlock` 现在会顺带解翻译 Key；`lockConfig()` 一并清空。
- `publicConfig()` 只回 `has_key / encrypted / base_url / model / app_id`，**任何 Key 都不回前端**；浏览器内存里也不再保留明文（`loadCfg` / `loadCfgStore` 读到旧值只记 `hasKey` 标记，`apiKey` 一律置空）。
- 前端设置面板在需要 Key 的服务下多一个「主密码」输入框（只用于本次加密，不落盘）；保存走 `POST /api/translate/config`，失败把原因写在 `#cfgNote`（红色）。
- 翻译请求（batch / test / segment）不再依赖前端传 Key：`mergeCfg()` 按「请求体 → config.json → 旧 prefs」三级兜底，Key 只从后两级拿。

旧数据迁移（两条路，都验证过）：

### 10.12 合并段顺序修复 + 「合并顺序」编辑器 + 启动日志

**1. 根因**

`mergeBlocks()` 拼好片段后又执行了一次 `merged.spans.sort((a, b) => a[0] - b[0])`，也就是**按行号**重排。但行号顺序 ≠ 用户看到的顺序 —— 手动「排序」过的页、以及跨栏合并，段落数组顺序才是展示顺序。于是合并后文字被重新排成行号序，出现「本该第一的跑到第三」。

修法：删掉那次排序，直接按 `idxs`（段落数组顺序）依次追加各段的片段，并在代码里写明原因。

**2. 新增：合并段内部顺序编辑器**

- 卡片 meta 上多一个 `顺序 N` 按钮，**只在该段由 ≥2 个片段合并而成时出现**（`b.spans.length > 1`；为此把 `spans` 加进 `toPublicBlocks` 的输出）。
- 点开弹窗列出每个片段：序号圆点 + 前 160 字预览（hover 看全文）+ `↑`/`↓`（首行禁用 ↑、末行禁用 ↓）。
- 应用时：`snapshotUndo` → 改写 `group.spans` → `p.groupsEdited = true` → `applyEdit(p)` 重建版面并落库，然后定位回这一段。没改顺序直接关闭则不写快照。
- 弹窗样式在 `shell.css`（`#view-translate .order-row …`）；因为 `.mini` 默认 `opacity: 0`（只在卡片 hover 时显形），这里的按钮加了 `always` 类并强制 `opacity: 1`。

**3. 启动日志**

`server/index.mjs` 启动横幅改成三视图：

```
  PaperLens · 翻译 + 精读 + 知识图谱
  ➜  翻译：      http://127.0.0.1:5173/?view=translate
  ➜  精读：      http://127.0.0.1:5173/
  ➜  知识图谱：  http://127.0.0.1:5173/?view=kg
```

**验证**（隔离实例，示例 PDF）：合并前两张卡片 → 27 段变 26 段、首段文字仍是第一段（顺序没被打乱）；卡片出现 `顺序 3`；弹窗 3 行、`↑` 首行禁用；把第 1 行下移后应用 → 合并段文字变成以原第 2 段开头，刷新后仍保持。

### 10.13 「顺序」入口找不着：改成显式可见 + 首页引用加版本号

**为什么之前"看不见"**

1. 按钮只在**真正由 ≥2 个片段合并而成**的段落上出现；普通段落没有。真实数据里这种段落并不多（kiytsn0 121 段中有 7 段、k7pm00i 71 段中有 10 段、krze5jj 21 段中有 2 段），前几屏往往都碰不到。
2. 它原本用 `.mini` 样式，而 `.mini` 是「卡片 hover 才显形」，视觉上几乎等于隐藏。
3. 页面里的 ES 模块一旦加载就驻留内存，改完代码只切视图不刷新时看到的还是旧界面。

**改法**

- 按钮文字改成 `⇅ 顺序 N`，加 `order-mini` 类：强调色文字 + 描边 + 浅底，**常显**（不再依赖 hover）。
- 编辑模式（`编辑分段`）下，每个卡片下方工具条里再多一个 `⇅ 合并顺序 N`，和「↑上移 / ↓下移 / ↑并到上一段 / ⤢贴合 / 拆分」并排 —— 合并完顺手就能调。
- `server/index.mjs` 新增 `serveIndexHtml()`：首页返回时给本地 `*.js / *.css / *.mjs` 的引用追加 `?v=<文件 mtime>`。**以后改前端只要普通刷新**，不用清缓存；该改动在服务下一次重启后生效。

验证（真实数据 kiytsn0）：卡片区 7 个 `⇅ 顺序 2`（紫色、opacity 1、宽 61px），编辑模式另有 7 个 `⇅ 合并顺序 2`；点开弹窗为 3 行片段、首行 ↑ 禁用，下移后应用，合并段文字顺序随之改变并落库。

### 10.14 合并段只显示一块框：按片段出框（含跨页 / 区域合并）

**现象**：SlideSLAM 摘要那段是三次合并来的，但左栏只框出一块。

**根因有三层，逐层排掉**

1. `rebuildPage()` 里有一句 `if (g.box) continue`：只要这个分组被拖动过一次（留下整体外框 `g.box`），续接框就不再生成。`buildBlocksFromSpans` 又优先用 `g.box` 当主框，于是多块被一个外框糊成一块。
2. 跨页 / 含框选段的合并（`mergeAcrossPages` / `mergeWithArea`）构造 `extraBoxes` 时只给**每个整块一个 bbox**，没有按它的行区间拆开。若被并进来的那段自身占两处（之前同页合并过），就永远只画一个框。
3. 载入时 `normalizeGroupsArray` 把区域段的 `spans` 丢掉了，宿主自己占哪几块无从还原（只剩 `lines` 可用）。

**改法**

- 合并统一记「片段」：`area.parts = [{ page, spans, box, text }]`，`area.text = joinPartText(parts)`（跨行断词按原文接回去）。一个块自己占多处时**按块拆成多条**，所以「合并三段」在顺序列表和框上都是三条。
- `rebuildPage()`：
  - 同页合并：`spans.length > 1` 时按片段算框，**忽略 `g.box`**（主框取第一片，其余进 `extraBoxes`）。
  - 区域合并：`adoptAreaParts()` 从 `parts`（老数据从 `spans`/`lines` + `removed`）还原片段，一块一个框；用户拖动过（`area.boxEdited`）则以拖出来的框为准，「贴合」会清掉标记回到自动。
- `normalizeGroupsArray` 保留区域段的 `spans`；`commitResize` 在拖动后片段仍多于一块时不记 `g.box`。
- 顺序编辑器泛化为 `mergeParts()`：同页合并读 `group.spans`，区域合并读 `area.parts`，弹窗、上移下移、应用逻辑同一套；应用区域段时按新顺序重拼正文。

**实测**（SlideSLAM，真实数据的一次性副本）

| 检查 | 改前 | 改后 |
| --- | --- | --- |
| 摘要段（3 次合并） | 1 个框（整体 bbox） | **3 个框**：P2 左栏底 1 行、P2 右栏 5 行、P3 27 行；卡片显示 `⇅ 顺序 3` |
| 另一段（同页 2 片段 + 曾拖过框） | 1 个宽框 | 2 个框，`⇅ 顺序 2` |
| 顺序弹窗 | 区域段无入口 | 3 行片段，可上下移，应用后正文按新顺序重拼并落库 |
| 同页新合并两段 | 2 个框 | 2 个框（无回归） |

`npm run check` 50 文件 0 失败、`npm run smoke` 通过、无头 Chrome 0 异常 0 控制台错误。

### 10.15 精读页热区跟随翻译页的「改后分块」

**问题**：`papers.blocks_json` 里存的是翻译页写回的块，但写回时丢了 `extraBoxes`，所以精读页只能看到合并段的主框；而且编辑分段后根本没触发写块，精读页一直停在旧数据上。

**三处改动**

1. **写块带上多块**：`blocksPayload()` 增加 `extraBoxes: [{ page(0 基), x0, x1, yTop, yBottom }]`。合并段在翻译页占几块，库里就记几块。
2. **签名换成内容指纹**：原来是 `page:order:text.length`，调整合并顺序（文本长度不变）不会触发写库；现在是 `JSON.stringify(blocks)` 的 djb2 hash + 长度，坐标、顺序、extra 的任何变化都会写。
3. **编辑即同步**：`saveOverrides()` 末尾加 `scheduleBlocksSave(600)`。所有分段改动（合并 / 拆分 / 拖动框 / 调顺序 / 删除）都会经过它，600ms 防抖避免拖拽时连写。

**精读页侧**：`blocksToParas()` 支持 `extraBoxes`，为每一块生成一个 `rect`（各自按所在页的高度做 y 翻转），一个段落在 PDF 上就有多个热区框，`pageData.boxes.push({para, rect})` 原本就按 rect 循环，无需改渲染。

**实测**（SlideSLAM，数据副本）

| 检查 | 结果 |
| --- | --- |
| 翻译页打开后写库 | 258 段 / 270 个矩形 / 11 段带 extra |
| 精读页热区 | 270 个 `.pdf-para`，258 个 para id，11 段多框 |
| 三合一摘要段 | 精读页 3 个框（143×8、149×34、149×148），与翻译页位置一致 |
| 再合并两段后 | 库 257 段 / 仍 270 矩形；精读页 270 个框，新合并段多出 1 个 extra |
| `npm run check` / `smoke` / 无头 Chrome | 50 文件 0 失败 / 通过 / 0 异常 0 控制台错误 |

**历史数据**：库里的 `blocks_json` 还是旧格式（无 extraBoxes）。在翻译页打开那篇论文一次即可回写（`blocksSig` 为空，首次必写），之后精读页刷新就是同一份块。
