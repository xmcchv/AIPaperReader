# PaperLens × 知识图谱 合并设计方案

> 目标：把「论文精读」与「知识图谱」合成**一套本机论文阅读工具**——同一仓库、同一进程、同一端口、同一套模型配置；读完一篇论文可以一键入库图谱，图谱里的概念与出处可以跳回原文。

---

## 1. 结论先行

推荐**三步走**，每一步都可独立验收、可回退：

| 阶段 | 做什么 | 风险 | 工作量 |
| --- | --- | --- | --- |
| P0 物理合并 | 单仓库 + 单进程 + 单端口；抽出共享的 `config / secret / llm / http`；两个页面独立路由 | 低 | 0.5–1 天 |
| P1 双向联动 | 精读页「→ 知识图谱」进程内入库；图谱出处「回到原文」；统一图切换语义 | 中 | 1–1.5 天 |
| P2 论文库落盘 | 新增 `papers` 表：精读结果、结构化结果、追问、PDF 都落盘；URL 深链 | 中 | 1.5–2 天 |
| P3 一体化外壳（可选） | 单页工作台、统一搜索、报告内嵌图谱 | 中高 | 2–3 天 |

**不建议第一步就做单页 SPA。** 两个前端各自约 1500 行状态机、1500/1441 行 CSS，且有 24 个同名 class（`topbar` / `btn` / `dialog` / `field` / `toast` …）定义不同；先做成同源的 `/` 与 `/kg/` 两个页面，收益最大、风险最低。

## 2. 现状盘点

### 2.1 两边的共同点（合并的基础很好）

| 维度 | PaperLens | KnowledgeGraph |
| --- | --- | --- |
| 运行时 | Node + 原生 ESM，零依赖 | 同左 |
| 服务端 | `server/index.mjs`，`http.createServer` + 手写路由 | 同左，几乎同一套模板 |
| 前端 | 原生 HTML/CSS/ESM，无构建 | 同左 |
| 加密 | `scrypt(N=16384,r=8,p=1)` + `AES-256-GCM` | **格式完全一致** |
| 模型协议 | OpenAI 兼容 `/chat/completions` | 同左 |
| 监听 | `127.0.0.1:5173` | `127.0.0.1:5180` |

`secret.mjs` 两边除了注释与换行几乎逐字相同；`llm.mjs` 是同一份代码的两条演进分支——PaperLens 版多了 `streamChat`（SSE、`reasoning_content` 思维链）与 `extra_body`，图谱版多了视觉模型（`image_url` content）与更简单的 `completeChat`。**合并时取并集即可，不存在架构冲突。**

### 2.2 差异与缺口

| 项 | PaperLens | KnowledgeGraph | 合并影响 |
| --- | --- | --- | --- |
| Node 门槛 | ≥18 | ≥22.5（`node:sqlite`） | 统一到 ≥22.5；本机 Node 24 满足 |
| 配置位置 | `~/.paperlens/config.json` | `~/.kgraph/config.json`，读不到时回退 PaperLens 的 | 统一成一份，保留兼容读取 |
| 数据落盘 | 几乎不落盘：论文在浏览器 `localStorage`，PDF 在 IndexedDB | SQLite `data/graphs/*.db` + 每日快照 | 数据目录与备份策略要向图谱看齐 |
| 精读结果 | 只在内存，刷新即丢 | 由推送时的 `reading` 片段保存 | P2 必须补 `papers` 表 |
| API 命名 | `/api/analyze`、`/api/structure`… | `/api/state`、`/api/import`… | 仅 `/api/config*` 冲突，需要定命名空间 |
| 联动 | **没有**「→ 知识图谱」入口 | 已有 `/api/import/paperlens` 与 `paperlensExtraction` | 图谱 README 描述的按钮在本仓库并不存在，需补 |
| 前端入口 | `public/index.html` 直接驱动 | `public/index.html` 直接驱动 | 同源双页面，无需改状态机 |

> 关键事实：图谱侧 `paperlensExtraction()`（`extract.mjs:228`）已经能吃 PaperLens 的 `structure`：概念按 `terms` 在原文里取整句作 `refs`，`diagram` 转成 `flow` 边。**合并的联动逻辑大部分已经写好，缺的是「谁在什么时候调用它」。**

### 2.3 现在真正的痛点

1. **精读成果不持久**：刷新页面只剩原文，7 节精读、概念、图解全丢；只有手动导出的报告能留档。
2. **原文存浏览器**：`localStorage` 有 5MB 量级限制，代码在 >80 万字符时**静默不保存**（`public/app.js:190`）。
3. **两套配置**：同一个 Key 要在两个服务里各解锁一次；视觉模型只在图谱侧能配。
4. **联动靠 HTTP**：跨端口 `fetch` + CORS，服务没起就断，且 `?graph=` 会全局切换激活图谱，两个页面同时用会互相串台。

## 3. 目标架构

### 3.1 一个进程、一个端口、两个页面

```
浏览器
 ├── http://127.0.0.1:5173/         精读工作台（现有三栏 UI）
 └── http://127.0.0.1:5173/kg/      知识图谱（现有图谱 UI）
        │
        └── 同一个 Node 进程
              ├── /api/paper/*   精读、结构化、追问、arXiv
              ├── /api/kg/*      图谱、资料、概念、检索、导入
              ├── /api/config*   共享配置（一份 Key、一套预设）
              └── /assets/*      图片素材
```

- 端口统一为 **5173**（论文阅读是主入口），可用 `PORT` 覆盖；旧图谱书签 `5180` 不再监听，README 里给一句迁移说明。
- 同源之后**不再需要 CORS**；两个页面共享 `localStorage` / IndexedDB，主题、论文、解锁状态天然互通。
- 页面之间用普通链接 + URL 参数跳转，不共享 JS 状态机。

### 3.2 目录结构

```
AIPaperReader/
  package.json                 # engines: node >= 22.5
  server/
    index.mjs                  # 唯一入口：路由 + 静态 + 启动
    http.mjs                   # sendJson / readBody / openSse / serveStatic / MIME
    shared/
      config.mjs               # 统一配置（含 vision_*）
      secret.mjs               # 原样复用
      llm.mjs                  # streamChat + completeChat（含视觉）
    paper/
      routes.mjs  paper.mjs  prompts.mjs  samples.mjs
    kg/
      routes.mjs  store.mjs  extract.mjs  web.mjs  demo.mjs
  public/
    index.html app.js styles.css ...      # 精读（原样，只加导航按钮）
    kg/
      index.html app.js graph.js starfield.js styles.css
  tools/
    restore-from-reports.mjs
  docs/
    合并设计方案.md
    开发纪要.md
  data/                        # 见 3.4
```

迁移方式：`git mv` 保留历史。PaperLens 现有文件放回 `server/paper/` 与 `public/` 根；图谱文件整体进 `server/kg/`、`public/kg/`。图谱前端的相对引用（`./graph.js`、`styles.css`）在 `/kg/` 下无需改动。

### 3.3 服务端模块合并

**`http.mjs`（新增）**：两边重复的 `sendJson` / `readBody` / `serveStatic` / MIME / `HttpError` 抽出来。`readBody` 上限取图谱的 26MB（图片素材需要）。

**`shared/llm.mjs`**：以 PaperLens 版为底，补上图谱版能力：

- 保留 `streamChat`（SSE 增量、`reasoning_content` 单通道、`finishReason`）
- 保留 `extra_body` 合并（PaperLens）
- `completeChat` 支持 `image_url` 内容块（图谱视觉模型）
- `LlmError` 与错误文案统一

**`shared/config.mjs`**：字段取并集：

```js
{
  provider, base_url, model,
  max_tokens, temperature, extra_body,
  api_key_enc,                 // 加密；永不回前端
  vision_model, vision_base_url, vision_api_key_enc,
  config_version
}
```

- **规范路径**：`~/.paperlens/config.json`（沿用已有 Key，避免用户重设主密码）。
- **兼容读取顺序**：`~/.paperlens/config.json` → `~/.kgraph/config.json` → 环境变量（`PAPERLENS_*` 优先，接受 `KGRAPH_*` 别名）。
- 首次保存时把内容写回规范路径；只读回退时**绝不覆盖**另一个文件。
- 环境变量：`PAPERLENS_API_KEY / PAPERLENS_BASE_URL / PAPERLENS_MODEL / PAPERLENS_PASSPHRASE` 继续有效。
- `publicConfig()` 返回并集（`has_key / has_vision_key / locked / ready / vision_ready / config_path / data_dir`），PaperLens 前端忽略不认识的字段即可。

**`shared/secret.mjs`**：直接复制其中一份，**不要改 KDF 参数与字段格式**，否则用户已加密的 Key 会解不开。

**路由表**（统一后）：

| 方法 | 路径 | 归属 |
| --- | --- | --- |
| GET | `/api/config`、`/api/kg/state` | 共享 / 图谱 |
| POST | `/api/config`、`/api/config/test`、`/api/config/unlock` | 共享 |
| POST | `/api/analyze`、`/api/structure`、`/api/ask`、`/api/export/summary` | 精读 |
| POST | `/api/paper/fetch`、GET `/api/sample` | 精读 |
| POST | `/api/kg/import`、`/api/kg/import/paper` | 图谱 |
| GET | `/api/kg/graphs` … `/api/kg/search`、`/api/kg/storage` | 图谱 |
| GET | `/api/health` | 共享（`service: "paperlens"` + `kg: true`） |

保留旧图谱路径作为**别名**（至少保留一个版本）：`/api/import/paperlens`、`/api/search`、`/api/state`，内部重定向到新 handler。论文侧现有路径完全不变。

### 3.4 数据布局与安全

```
~/.paperlens/config.json        模型配置（加密 Key）
<DATA_DIR>/graphs/<id>.db       每个图谱一个 SQLite
<DATA_DIR>/backups/             每日快照（各留 7 份）
<DATA_DIR>/assets/              图片素材
<DATA_DIR>/papers.db            P2：论文库（可选，见 5.2）
<DATA_DIR>/pdf/<paperId>.pdf    P2：PDF 原件（可选，替代 IndexedDB）
```

`DATA_DIR` 默认从仓库内 `data/` **迁到用户目录** `~/.paperlens/data/`，原因：

- 仓库目录可能被 `git clean -xfd`、重装、换盘误删；图谱开发纪要里已经发生过一次「误删 `data/`」事故。
- 配置本来就在用户目录，数据跟着走，备份/换机器只拷一个目录。
- 迁移是**复制不改动**：首次启动检测 `repo/data/graphs` 有库而目标目录为空时，`cp -r` 过去并在日志里说明；原目录保留，用户确认后再手动删。

> 如果更希望数据跟着仓库走，只需把默认值改回 `ROOT/data`——这是本方案里唯一的「用户口味」选择，其余都不依赖它。

### 3.5 图谱切换语义（顺手修掉一个隐患）

现状：每个 `/api/kg/*` 请求带 `?graph=<id>` 时，服务端会**全局激活**该图谱（`index.mjs` 主循环）。单进程 + 双页面后，两个页面各自带不同 `?graph=` 会互相把对方的激活图切走；更糟的是，`importPayload` 在 `await` 模型抽取期间，激活图可能已被另一个请求改掉。

改法：

- 请求进入时解析 `graphId`，**显式传入** `store` 的每个操作（`importPayload(body, { graphId })`、`mergeGraph(graphId, ...)`）。
- `store.mjs` 的连接按 graphId 缓存（`Map<graphId, conn>`），不再依赖模块级单例 `db`；没有 `?graph=` 时才用 `activeGraphId`。
- `active.txt` 只由「切换图谱」按钮写，不再被普通请求顺带改写。

这是 P0 里唯一需要动 `store.mjs` 内部结构的地方，建议单独一个提交，便于回滚。

## 4. 前端合并方案

### 4.1 为什么不直接合成一个页面

- 两边 `app.js` 都在模块顶层绑定 `document` 上的 ID，并立刻 `init()`；放进同一页面需要改造成「按路由懒加载 + 生命周期」。
- CSS 有 24 个同名 class，`topbar`、`btn`、`dialog` 的尺寸/配色/层级定义都不同，合并需要给其中一套全部加前缀（约 1400 行）。
- 收益是「少一次跳转」，成本却高于 P1+P2 的总和。

### 4.2 双页面 + 轻量外壳

- `/` 与 `/kg/` 各自保留完整页面。
- 顶栏加一个固定入口：精读页 `知识图谱 →`；图谱页 `← 论文精读`。
- 两边主题键统一为 `paperlens.theme`（图谱侧读 `kg-theme` 作为回退），切换任一页另一页跟着变。
- 可选：两页共用一个「模型设置」对话框实现。P0 先保留两份界面、共用 `/api/config`；P1 把视觉模型字段补进精读页的设置，避免用户为了配图跑两趟。

### 4.3 URL 深链约定

| URL | 含义 |
| --- | --- |
| `/kg/?graph=<id>` | 打开指定图谱 |
| `/kg/?source=<sourceId>` | 只看某份资料引出的概念 |
| `/kg/?q=<keyword>` | 带搜索打开 |
| `/?paper=<paperId>` | P2：打开论文库中的某篇（含精读结果） |
| `/?paper=<paperId>&quote=<encoded>` | P2：打开并定位到某句原文 |
| `/?paper=<paperId>&concept=<conceptId>` | P2：打开并高亮该概念 |

P1 在没有 `papers` 表时，用 `/?fromSource=<sourceId>` 让精读页向 `/api/kg/sources/text` 取正文；能读、能问，但没有 PDF 原版视图与历史精读。

## 5. 联动设计（合并的核心价值）

### 5.1 P1：精读 → 图谱（进程内，不走 HTTP）

```
点「→ 知识图谱」
  → POST /api/kg/import/paper { title, text, source, reading, structure, graphId?, enrich? }
  → importPayload({ kind: 'paperlens', ... })     // 直接函数调用
      ├─ addSource()                               // 正文 + 元数据
      ├─ paperlensExtraction()                     // concepts/claims/diagram → 节点 + flow 边
      │    └─ 用 terms 在正文里取整句 → refs（出处是原文，不是模型复述）
      ├─ enrichPrereqs()（模型可用时）              // 补 PaperLens 没有的「前置关系」
      └─ mergeGraph()                              // 同名/同别名概念并入已有节点
  → 返回 { sourceId, stats, warnings }
  → 前端记住 paper → { graphId, sourceId } 的映射，按钮变成「已在图谱中 · 查看」
```

要点：

- 服务端直接调用，**删掉跨端口的 CORS 依赖**；`/api/import/paperlens` 保留为兼容别名。
- 图谱没配模型也能导入（资料先入库，之后「补抽取」）；P1 要保证这条路径在 UI 上可见。
- 目标图谱显式传入：当前激活图或用户在对话框里选的图，**不允许隐式全局切换**。

### 5.2 P2：论文库（真正把精读成果留住）

新增一张**跨图谱**的表 `papers.db`（独立于 `graphs/<id>.db`，避免破坏「一图一库」）：

```sql
CREATE TABLE papers (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  source TEXT NOT NULL DEFAULT '',        -- arxiv 链接 / 文件名
  kind TEXT NOT NULL,                     -- text | pdf | arxiv
  text TEXT NOT NULL,
  chars INTEGER NOT NULL,
  pdf_path TEXT NOT NULL DEFAULT '',
  reading_md TEXT NOT NULL DEFAULT '',
  reading_model TEXT NOT NULL DEFAULT '',
  structure_json TEXT NOT NULL DEFAULT '{}',
  ask_json TEXT NOT NULL DEFAULT '[]',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- 精读页打开时先 `GET /api/paper/library`；有 `?paper=<id>` 就加载，没有就恢复上次（`localStorage` 只存当前 `paperId`，不再存全文）。
- 流式精读结束后 `PUT /api/paper/:id` 落盘（防抖 1s + 关闭前 `sendBeacon` 兜底）。
- 图谱 `sources.meta.paperId` 记录来源论文；出处面板据此显示「回到原文」。
- PDF 落到 `<DATA_DIR>/pdf/<id>.pdf`，`pdfview.js` 改为从 `/api/paper/:id/pdf` 读取；IndexedDB 仅作离线缓存。这会一并解决 localStorage 80 万字符静默丢弃的问题。
- 论文库与图谱是**多对多**：一篇论文可推送到多个图谱，一个图谱也可收多篇论文；不提供「删论文即删概念」，删除时只清 `meta.paperId` 关联。

### 5.3 反向跳转（图谱 → 原文）

- 概念详情的每条「出处」增加动作：
  - 有 `paperId` → `/?paper=<id>&quote=<句子>`：精读页加载论文后按句子检索并高亮，滚到可见区域。
  - 无 `paperId`（网页/笔记/旧数据）→ 保持现在的资料正文弹窗。
- 概念名/别名点击 → `/?paper=<id>&concept=<id>`：复用现有的「核心概念点击定位」逻辑（优先英文 `terms`，空格/连字符可选）。
- 图谱侧「只看这篇」与精读页的「这篇在该图谱中的概念」互相给出入口，形成闭环。

### 5.4 配置与检索统一

- 一份配置、一次解锁：`/api/config/unlock` 同时解 `api_key_enc` 与 `vision_api_key_enc`。
- 统一搜索（P3）：`/api/search` 返回 `papers`（标题/精读正文）+ `concepts` + `source text` 三类命中；图谱页现有的搜索框与精读页新加的全局面板共用。
- 报告（P3 可选）：导出报告时把该论文在知识图谱中的「概念 + 前置链」截成静态 SVG 附在方法链路图之后。

## 6. 实施步骤（按提交拆分）

### P0 · 物理合并（0.5–1 天）

1. **仓库合并**：在 `AIPaperReader` 上 `git merge --allow-unrelated-histories`（或 `git subtree add`）引入图谱历史；先放进临时目录 `kgraph/`，保证任何时刻可回滚。
2. `git mv` 到 3.2 的目录结构；`package.json` 改名/`engines>=22.5`；`.gitignore` 合并图谱的 `data/graphs|backups|assets` 规则，保留 `data/config.example.json`。
3. 抽出 `server/http.mjs`；合并 `config.mjs` / `secret.mjs` / `llm.mjs`。
4. 新 `server/index.mjs`：先静态路由（`/`、`/kg/`、`/assets/`），再 `/api/config*`，再 `/api/paper/*`、`/api/kg/*`；旧图谱路径留别名。
5. 前端：图谱 `app.js` 的 `api()` 与静态资源路径改为 `/api/kg` 前缀；精读页不动。
6. `store.mjs` 改为按 graphId 取连接（3.5），单独提交。
7. 数据目录迁移（3.4）。

**验收**：`node --check` 全部通过；一个进程同时打开两页；模型设置只填一次；图谱 CRUD 与精读全流程不回归。

### P1 · 双向联动（1–1.5 天）

1. 精读页加「→ 知识图谱」按钮与目标图谱选择；调用 `/api/kg/import/paper`。
2. 保存 `paper → {graphId, sourceId}` 映射（P1 先放 `localStorage`，P2 进 `papers` 表）。
3. 图谱出处面板加「回到原文」；P1 走 `/?fromSource=<id>`。
4. 删除内部 CORS 依赖与「图谱未启动」提示（已同进程）。
5. 两个设置对话框共用 `/api/config`，精读页补视觉模型字段。

**验收**：示例论文 → 精读 → 推送 → 图上出现概念与 `flow` 边，每条 refs 能在正文中逐字命中；刷新后图谱仍在；图谱侧能跳回原文。

### P2 · 论文库（1.5–2 天）

1. `papers.db` + `/api/paper/library` CRUD + PDF 文件存取。
2. 精读结果、结构化、追问自动保存；`?paper=` / `?quote=` / `?concept=` 深链。
3. 图谱 `sources.meta.paperId` 与出处跳转打通。
4. 启动时把浏览器里的当前论文导入论文库（一次性）。

**验收**：刷新、重启、换浏览器后精读结果与 PDF 原版都还在；断网也能打开已读论文；论文库删除不影响图谱。

### P3 · 一体化外壳（可选，2–3 天）

统一搜索、报告内嵌图谱、单页 tab 外壳（需要 CSS 前缀化改造，放到最后做）。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 误删/误清 `data/` | 知识库永久丢失 | 数据移出仓库；每日快照；迁移只复制不移动；README 写明「绝不删 data/」 |
| 配置迁移丢 Key | 需重设主密码 | `secret.mjs` 字节级复用；只读回退不覆盖；首次保存写规范路径 |
| `?graph=` 串台 | 两页互相切库、写错图谱 | 显式 graphId + 按图连接（3.5） |
| `node:sqlite` 版本门槛 | 低版本 Node 启动失败 | `engines>=22.5` + 启动时明确报错文案；README 置顶 |
| 单进程故障域 | 图谱挂掉连带精读 | 全部在 `try/catch` 内返回 JSON；LLM 流断开只影响当次 SSE；SQLite 写是同步毫秒级，不阻塞流式 |
| 长流式请求 + 同步写 | 事件循环抖动 | 写库放在 SSE 结束之后（P2 的持久化用防抖），不在每个 delta 上写 |
| 两套 UI 风格漂移 | 体验割裂 | P0 只统一顶栏入口与主题；P3 再做设计系统 |
| 旧书签 5180 失效 | 用户以为坏了 | 启动日志与 README 说明新地址；可选在 5180 起一个只做 302 的轻量 server（默认关闭） |

## 8. 验证清单

每次合并提交至少跑：

```bash
# 语法
node --check server/index.mjs
# 逐个文件
find server -name '*.mjs' -exec node --check {} \;

# 启动
node server/index.mjs
```

功能核对（手工 + 脚本）：

1. `GET /api/health` 同时报告 services；`GET /api/config` 只返回打码 Key。
2. demo 模式：示例论文 → 流式精读 → 结构化 → 图解 → 导出报告。
3. 推送示例论文到图谱：概念数 > 0、`flow` 边存在、每条 refs 的句子在原文中逐字存在。
4. 图谱：新建/切换/重命名/删除；跨图概念与检索隔离；`?graph=` 不改变 `active.txt`；FTS 开关。
5. 两个标签页分别打开不同图谱 + 精读页推送：不串库。
6. 重启后：Key 锁定 → 解锁一次，两页都可调用模型。
7. 数据目录迁移：旧 `data/graphs/*.db` 出现在新目录，原目录未被删除。
8. 旧别名接口：`POST /api/import/paperlens` 仍可用。

## 11. 实施记录（v2.0，已完成）

方案已按 P0–P3 落地，实际实现与本文档的差异如下：

- **仓库**：以 `AIPaperReader` 为主仓库，知识图谱源码复制进 `server/kg/`、`public/kg/`、`tools/`、`docs/`；未合并对方的 git 历史（其仓库把 `data/*.db` 跟踪进了版本库，不适合并入）。
- **端口**：统一 `5173`；旧 `/kg/` 地址 302 到 `/?view=kg`，`/kg/app.js` 等资源保留。
- **数据目录**：`~/.paperlens/data/`（`graphs/`、`backups/`、`assets/`、`papers/`、`papers.db`），迁移为复制，原目录保留。
- **配置**：`~/.paperlens/config.json` 统一文本与视觉模型；`~/.kgraph/config.json` 只读回退。
- **论文库**：新增 `server/paper/library.mjs`（`papers.db`）与 `/api/paper/*`；精读页自动保存、`?paper=<id>` 深链、PDF 落盘。
- **单页外壳**：`public/index.html` 同时容纳两个视图；`public/shell.js` 处理 `?view=kg`；图谱 CSS 通过 `public/kg/styles.scoped.css` 作用域化到 `.kg-view`，ID 加 `kg-` 前缀。
- **联动**：`/api/kg/import/paper` 进程内入库；`source.meta.paperId` 记录论文库 id；图谱出处回跳 `/?paper=<id>&quote=<句>`。
- **未改动**：`store.mjs` 仍用模块级 SQLite 连接与 `?graph=` 自动激活（单页下同一时刻只操作一个图谱，风险已降低）。多标签页并发切图仍建议后续改成显式 graphId 连接。
- **验证**：`node --check` 全部服务端与前端模块；P0/P1/P2/P3 各阶段做了 API 与浏览器实测（demo 精读、推送 13 概念、刷新恢复 7 节精读、论文库列表、PDF 存取、`/kg/` 重定向、开关切换）。
